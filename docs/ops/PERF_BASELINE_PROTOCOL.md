# بروتوكول خط الأساس للأداء — أوامر جاهزة وجدول قياس (T11)

> **المهمة:** التحضير الكامل لـT11 (مسار WS-A) — «خط أساس الأداء: إقلاع/ذاكرة/بطارية/استعلامات»
> **التاريخ:** 2026-10-03 · **الحالة:** بروتوكول معتمد — القياس نفسه يحتاج جهازاً حقيقياً واحدة فقط (سياسة المشروع: لا أرقام بلا قياس)
> **جهاز المرجع:** أي جهاز فعلي على أندرويد 13–16 بميموري 3GB+ — يُثبَّت طرازه في الجدول قبل القياس ولا يُغيَّر حتى نهاية W1 كي تبقى المقارنة صحيحة

---

## 1) التحضير (مرة واحدة — 5 دقائق)

```bash
# تثبيت نسخة release الموقعة (لا debug — الأرقام تخالف)
adb install -r SuperBiz-v1.0.0-signed.apk

# اطمئن أن المبنى release غير قابل للتنقيح (حجمه شاهد)
adb shell dumpsys package com.superbiz.app | grep -E "versionName|lastUpdateTime"

# شغّل التطبيق مرة واتم بطاقة ترحيب/تهيئة يدوياً ثم أغلقه —
# القياسات أدناه للإقلاع «الحار الناضج» لا أول إقلاع يبني مخازن
```

قواعد لا تُكسر في كل قياس أدناه: شاشة مضاءة ومفتوحة، لا شاحن موصول (يبطئ ويغير الحرارة)، تفريغ من التطبيقات الحديثة (`adb shell input keyevent KEYCODE_HOME` ثم انتظار 30ث)، و**تكرار 5 مرات** وإدخال الوسيط (الترتيب الثالث) لا المتوسط — المتوسط يشيع بالأول القذر.

## 2) الإقلاع البارد — `am start -W` × 5

```bash
adb shell am force-stop com.superbiz.app && sleep 5
adb shell am start -W -n com.superbiz.app/.MainActivity
# سجل: ThisTime / TotalTime / WaitTime (بالمليثانية) — خذ TotalTime
```

يُكرر 5 مرات (force-stop بين كل مرة) ويُثبت الوسيط. عتبة الإنذار المبكر (لا بوابة رفض): وسيط > 1200ms على جهاز المرجع يستوجب بند تحقيق في دفعة T21 (وليس إصلاحاً فورياً — يُقرر في مراجعة الأحد).

## 3) الذاكرة بعد جولة استخدام حقيقية

```bash
# بعد: إنشاء فاتورة كاملة + فتح تقارير + فتح KPI (مسار Pro محاكى عبر نسخة debug مؤقتة إن لزم القياس بلا شراء)
adb shell dumpsys meminfo com.superbiz.app | grep -E "TOTAL PSS|Database|GL"
adb shell procrank | grep superbiz   # إن توفر (يحتاج بنية خاصة — اختياري)
```

يُثبت: **TOTAL PSS** بالميغابايت + سطر Database وحده (لرصد نمو الذاكرة المكشوفة لطبقة Room). عتبة: PSS ثابت < 250MB بعد الجولة كاملة على جهاز 3GB مريحة، وأي نمو بين قياسين متتاليين بنفس الجولة (تشغيل ثانٍ مطابق) > 40MB = مؤشر تسريب يفتح بنداً فورياً.

## 4) البطارية — جلسة استخدام مضبوطة

```bash
adb shell dumpsys batterystats --reset
# استخدم التطبيق 15 دقيقة بنمط ثابت (5 فواتير + طباعة حرارية + تقرير)
adb shell dumpsys batterystats --charged com.superbiz.app > battery_w1.txt
# تُقرأ منه: Battery time remaining / Wake locks / الجوال غير موجود (بلا إذن INTERNET دائم — فقط لقطات عند البيع)
```

المؤشر الموثق: **استهلاك الجلسة 15 دقيقة** بالنسبة المئوية + عدد Wake locks الكلي (نظرياً قريب من الصفر خارج WorkManager المجدول — أي ارتفاع مفاجئ يكشف مذبذباً خاطئاً).

## 5) الاستعلامات — توقيت Room من داخل اختبار الجهاز

الطريقة المعتمدة (لا شبكة، لا أدوات خارجية): اختبار قياس مؤقت على الشجرة يُنفذ على الجهاز نفسه عبر `connectedAndroidTest` أو أمر تشغيل مؤقت:

```bash
# قياس أثقل ثلاث استعلامات معروفة (تقارير المدى الطويل + بحث الأطراف)
adb shell am instrument -w -e class com.superbiz.app.PerfProbeTest \
  com.superbiz.app.test/androidx.test.runner.AndroidJUnitRunner
```

يُنفَّذ `PerfProbeTest` بثلاث دوال قياس فقط (تُحذف بعد T11 أو تبقى معطلة بتعليق — قرار مراجعة): إجمالي مبيعات سنة كاملة من 10K فاتورة مولدة، وبحث أطراف مطبعي، وقراءة كشوف طرف كثيف الحركة. يوثَّق لكل استعلام: الوسيط ms × 5 على الجهاز. هذا الرقم هو خط الأساس الذي تُقاس عليه دفعة تحسينات T21 (أسبوعا 7–8) — **بلا هذا القياس فبند T21 «تحسين الاستعلامات» قرار أعمى ويُرفض في المراجعة حجّة**.
